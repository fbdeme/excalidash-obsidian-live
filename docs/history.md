# 변경 이력 (방법론·설계 결정의 *이유*)

## 2026-09-22: 시작 — 왜 BUILD-FRESH 가 아니라 FORK 인가

Obsidian 이 전 기기에 깔리고 vault 가 동기화되면서(같은 날, `obsidian-livesync`) 보드를 어디서나 보는 문제는 이미 풀렸다. 남은 건 **ExcaliDash 와 vault 가 같은 그림을 들고 있게 하는 것**이고, 편집 지점이 둘이면 실시간이 아니고서는 계속 어긋난다.

만들기 전에 찾았다. 커뮤니티 플러그인 7,901 개 전수 + GitHub + 웹. 결과:

- ExcaliDash ↔ Obsidian 을 잇는 플러그인은 **하나 있었다**(`siredvin/excalidash-obsidian-sync`, MIT, 스토어 등재). REST 클라이언트·인증·씬 파싱·양방향 옵션까지 있다.
- 다만 **실시간은 아무도 안 했다.** upstream 스스로 "수동 명령", "양방향 충돌 해소 제한적"이라고 README 에 적어 뒀다.

그래서 처음부터 만들지 않고 **FORK** 한다. 배관을 다시 짜는 건 낭비고, 우리 고유 기여는 실시간과 충돌 해소다.

## 2026-09-22: 충돌 해소를 새로 설계하지 않기로

양방향 실시간의 어려운 부분은 이미 풀려 있다 — 2026-09-21 에 ExcaliDash 업로더에서 **두 번 사고**를 내고 얻은 규칙이 있다(요소 단위 version reconcile · 영구 tombstone · 409 낙관적 가드 · 업로드 후 검증). 핵심은 **요소 단위 reconcile 이 공통 조상을 요구하지 않는다**는 점이고, 그래서 실시간에도 그대로 성립한다.

따라서 이 프로젝트는 새 동기화 이론을 만들지 않는다. 저장은 검증된 REST 경로로 하고, socket 은 **알림과 전파**에만 쓴다. Excalidraw 의 reconcile 을 다시 구현하는 선택지는 처음부터 배제한다 — 버그 하나가 씬을 망가뜨린다.
